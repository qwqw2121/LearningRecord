# 项目长期笔记 · learning

## 项目性质

AI 资讯智能体项目的**学习/面试准备仓库**（`D:\AIProject\learning`），不是生产代码仓库。
围绕一个真实项目（RSS 采集 → Prefect Pipeline → LLM 分析 + Chroma → LangGraph Agent → MCP → FastAPI → 前端）做 12 天拆解学习。

## 目录约定

- `notes/01-project.md` ~ `12-evaluation.md`：严格一一对应 Day 1–12，文件标题即 `Day N｜主题`
- 每篇固定四段式（顺序固定，勿改）：
  1. `## 技术面试回答结构`（置顶，5 条带提示语的问答框架）
  2. `## 一、学习内容与记录`（每个知识点一张 `### N.` 卡片，
     含 **定义/目的/原理/实践/局限与取舍** 五个待填空字段）
  3. `## 二、实践任务`
  4. `## 三、学习复盘`（今天还没搞懂的内容 / 需要面试前回顾的内容）
- 两次周复盘统一放在根目录 `复盘.md`，不放进 notes
- `demos/{python,rag,agent}/`：可运行示例，各含 `.gitkeep`
- `interview/questions.md`：汇总 Day 2/6/8/12 产出的面试题
- `interview/mistakes.md`：踩坑记录，格式固定为「现象 → 原因 → 正确做法」

## 写作偏好

- 笔记文件之间用相对链接做 prev/next 导航
- **不要**在笔记里编造项目尚未实现的能力（Day 10 明确要求：确认实际使用的持久化功能，不把未实现功能描述为已有能力）
- 用户倾向于先建结构、再逐日填充，不要一次性把内容写满
- **结构越简单越好**：用户明确说过「不想太复杂的结构给自己压力」，不要加多余分区、
  勾选框或自造的索引表格，标题下只保留一行定位标签
