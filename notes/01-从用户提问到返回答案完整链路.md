结合你的 AI 资讯项目，目前采用的是 LangGraph 单 Agent + Tool Calling + MCP 工具架构。

从用户提问到 Agent 返回答案，可以分成六个阶段：

1. 用户请求进入 FastAPI 后端。
2. 后端调用 LangGraph Graph。
3. Agent Node 将用户问题和历史消息交给 LLM。
4. LLM 判断是否需要调用工具。
5. Tool Node 执行对应 MCP 工具，并将结果返回给 Agent。
6. Agent 根据工具结果生成最终答案，返回前端。

## 2. 每个阶段具体做什么？

### 第一阶段：接收用户问题

用户在 Next.js 输入：

> 最近一周有哪些值得关注的大模型新闻？

前端向 FastAPI 发送请求，通常包含：

```
{    "message": "最近一周有哪些值得关注的大模型新闻？",    "thread_id": "user_001"}
```

`thread_id` 用于区分不同对话，方便恢复历史上下文。

### 第二阶段：进入 LangGraph

后端调用 Graph，将用户消息传入 State。

你的 Agent State 核心结构是：

```
class AgentState(TypedDict):    messages: Annotated[list, add_messages]
```

这里的 `messages` 保存对话历史，包括：

- HumanMessage：用户问题
- AIMessage：模型回复
- AIMessage（tool_calls）：模型发出的工具调用请求
- ToolMessage：工具执行结果

如果启用了 Checkpointer，Graph 可以根据 `thread_id` 恢复之前的对话状态。

### 第三阶段：Agent Node 调用 LLM

你之前的代码中有：

```
agent_llm = _base_llm.bind_tools(TOOLS)
```

这一步的作用是将可用工具的名称、描述和参数 Schema 绑定给模型。

随后：

```
response = agent_llm.ainvoke(state["messages"])
```

模型根据用户问题和工具描述进行判断。

例如，它可能决定调用：

```
search_news_semantic
```

注意：`bind_tools()` 只是让模型知道有哪些工具可以使用，并不代表工具已经执行。

### 第四阶段：工具调用

模型返回的内容可能包含：

```
AIMessage(    content="",    tool_calls=[        {            "name": "search_news_semantic",            "args": {                "query": "最近一周大模型领域的重要进展"            }        }    ])
```

LangGraph 根据工具调用请求，将执行流程路由到 Tool Node。

Tool Node 调用你注册的 MCP 工具，实际执行对应的 MCP Server 方法。

你的项目目前主要有这些工具：

| 工具                     | 作用          |
| ---------------------- | ----------- |
| `search_news`          | 根据关键词检索新闻   |
| `search_news_semantic` | 根据语义相似度检索新闻 |
| `get_daily_report`     | 获取已有日报      |
| `request_daily_report` | 请求生成日报      |

例如，`search_news_semantic` 执行后，从 Chroma 检索相关向量，取得 `news_id`，再回到 SQLite 获取新闻内容。

### 第五阶段：工具结果返回 Agent

工具执行完成后，返回结果，例如：

```
ToolMessage(    content="找到 5 条相关新闻……",    tool_call_id="call_123")
```

LangGraph 将工具结果合并到 `messages` 中，再次进入 Agent Node。

此时 LLM 能看到：

- 原始用户问题
- 自己之前发出的工具调用
- 工具返回的数据

然后判断是否需要继续调用其他工具，或者已经可以回答。

这个过程可以循环多次。

### 第六阶段：生成最终答案

当 LLM 不再返回工具调用请求，而是直接生成文本时，Graph 判断流程结束。

最终结果：

```
最近一周值得关注的大模型新闻主要有：

1. ...
2. ...
3. ...
```

Graph 将最终状态返回 FastAPI，FastAPI 再将答案返回 Next.js 展示。

## 3. 你需要特别区分的三个技术

| 技术                   | 在调用链路中的作用              |
| -------------------- | ---------------------- |
| LangGraph            | 控制 Agent 的执行流程、状态传递和循环 |
| LangChain ChatOpenAI | 连接大模型，发送消息并接收工具调用请求    |
| MCP                  | 统一工具接口，让 Agent 能调用外部能力 |

可以简单记忆：

- LangGraph 决定下一步做什么。
- LLM 决定是否需要调用工具，以及调用哪个工具。
- MCP 负责提供和执行具体工具能力。

## 4. 面试回答版本

如果面试官问：

从用户提问到 Agent 返回答案，完整调用链路是什么？

可以这样回答：

> 用户首先通过 Next.js 前端向 FastAPI 发送问题，后端将用户消息传入 LangGraph。
>
> LangGraph 根据 thread_id 加载历史对话状态，然后进入 Agent Node。Agent Node 调用绑定了工具的 ChatOpenAI 模型，模型根据用户问题和工具描述判断是否需要调用工具。
>
> 如果需要调用工具，模型会返回 Tool Call 请求，LangGraph 将执行流程路由到 Tool Node，由其调用对应的 MCP 工具。MCP Server 执行具体业务逻辑，例如新闻关键词检索、向量语义检索或日报查询，并返回结果。
>
> 工具结果会作为 ToolMessage 加入 messages State，然后重新进入 Agent Node，让模型结合工具结果继续推理。
>
> 如果模型不再请求调用工具，而是直接生成文本，Graph 就结束执行，最终答案通过 FastAPI 返回前端。

## 5. 一个容易被追问的问题

如果模型连续调用了三个工具，是怎么执行的？

例如用户问：

> 总结本周大模型新闻，并与上周进行对比。

Agent 可能需要：

1. 调用 `search_news` 获取本周新闻。
2. 调用 `search_news` 获取上周新闻。
3. 调用 `search_news_semantic` 补充相关事件。

具体是并行还是串行，取决于模型返回的 Tool Calls、Tool Node 的执行方式以及你的代码配置，不能简单说一定并行。

建议你记住这条主线：

**用户问题 → FastAPI → LangGraph → Agent Node → LLM → Tool Call → MCP Server → 工具结果 → Agent Node → 最终回答 → 前端**

这就是你项目在线 Agent 问答的核心调用链路。它与 Prefect 负责的新闻采集、分析、Embedding 等离线数据处理流程是相互独立、通过数据库和向量库衔接的。
