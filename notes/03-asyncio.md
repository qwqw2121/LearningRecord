### 1. 进程、线程、协程的区别

**定义：**

- 进程：操作系统进行资源分配和调度的基本单位。
- 线程：进程内部的执行单元，同一进程中的线程共享进程资源。
- 协程：由程序控制的轻量级执行单元，可以在特定位置暂停和恢复。

**目的：**

通过不同的并发方式提高程序执行效率：

- 进程适合 CPU 密集型任务。
- 线程适合 I/O 密集型任务。
- 协程适合大量 I/O 等待场景。

**原理：**

- 进程拥有独立的内存空间和资源。
- 线程共享进程内存，由操作系统调度。
- 协程通过事件循环调度，在遇到可等待操作时主动让出执行权。

Python 常见实现中，线程由操作系统调度，`asyncio` 协程主要由事件循环调度。

**实践：**

AI 资讯项目中：

- RSS 请求、网络 API 调用属于 I/O 密集型操作，可以考虑并发。
- 新闻文本处理、数据清洗可以根据具体任务选择同步或并发方式。
- 如果是大量 CPU 密集型计算，可以考虑多进程。

**局限与取舍：**

- 多进程通信成本较高，内存开销较大。
- 多线程需要注意线程安全和锁竞争。
- 协程需要异步接口配合，不能自动加速同步阻塞代码。

### 2. 同步和异步的区别

**定义：**

- 同步：调用一个任务后，通常需要等待它完成才能继续执行后续代码。
- 异步：任务遇到等待操作时，可以暂时让出执行权，让其他任务继续执行。

**目的：**

提高程序在等待网络、文件、数据库等 I/O 操作时的资源利用率。

**原理：**

同步执行：

```python
import time

def task(name):
    time.sleep(2)
    print(name)

task("A")
task("B")
```

两个任务依次执行，总耗时约 4 秒。

异步执行：

```python
import asyncio

async def task(name):
    await asyncio.sleep(2)
    print(name)

async def main():
    await asyncio.gather(
        task("A"),
        task("B")
    )

asyncio.run(main())
```

两个任务可以在等待期间交替执行，总耗时约 2 秒。

**实践：**

项目涉及 RSS 抓取和外部模型 API 调用时，如果使用异步客户端，可以让多个 I/O 请求并发执行。

**局限与取舍：**

- 异步代码结构相对复杂。
- 同步阻塞操作可能拖住整个事件循环。
- 并不是所有任务都适合异步，简单任务使用同步方式可能更容易维护。

### 3. `async`、`await`、`asyncio`

**定义：**

- `async`：用于定义协程函数。
- `await`：等待一个可等待对象完成，同时允许当前协程让出执行权。
- `asyncio`：Python 标准库，提供协程、事件循环和异步任务管理能力。

**目的：**

使用协程处理 I/O 等待任务，提高并发执行效率。

**原理：**

```python
import asyncio

async def fetch_news():
    print("开始请求")
    await asyncio.sleep(2)
    print("请求完成")
    return "新闻数据"

async def main():
    result = await fetch_news()
    print(result)

asyncio.run(main())
```

执行过程：

1. `async def` 定义协程函数。
2. 调用协程函数得到协程对象，并不会立即执行函数体。
3. `asyncio.run()` 创建并运行事件循环。
4. 事件循环调度协程执行。
5. 遇到 `await` 时，如果等待的操作尚未完成，当前协程可以暂停。
6. 等待操作完成后，协程恢复执行。

**实践：**

项目中如果需要并发请求多个 RSS 源或调用多个外部 API，可以使用异步函数和异步客户端。

**局限与取舍：**

- `await` 只能用于协程函数等合法的异步上下文。
- 普通同步函数不能直接通过 `await` 等待。
- 异步函数内部仍然执行同步阻塞操作时，可能阻塞事件循环。

### 4. 事件循环是什么？

**定义：**

事件循环是 asyncio 的核心调度机制，负责管理和调度协程任务。

**目的：**

让多个协程在 I/O 等待期间交替执行，避免程序一直等待某一个任务完成。

**原理：**

事件循环大致执行以下过程：

1. 获取可运行的协程任务。
2. 调度协程向下执行。
3. 遇到 `await` 等待尚未完成的 I/O 操作时，暂停当前协程。
4. 继续执行其他就绪任务。
5. 等待的 I/O 操作完成后，将对应协程重新加入可运行队列。
6. 继续调度，直到任务完成。

**实践：**

在异步请求新闻源时，一个请求等待网络响应，事件循环可以调度其他请求继续执行。

**局限与取舍：**

- 一个事件循环中，阻塞操作会影响其他协程的执行。
- CPU 密集型计算不适合直接长时间运行在事件循环中。
- 可以通过线程池或进程池处理不适合直接在事件循环中执行的任务。

### 5. `asyncio.gather()` 如何实现并发？

**定义：**

`asyncio.gather()` 用于并发调度多个可等待对象，并在它们完成后收集结果。

**目的：**

当多个任务相互独立时，同时发起执行，减少整体等待时间。

**原理：**

```python
import asyncio

async def fetch(name, delay):
    await asyncio.sleep(delay)
    return f"{name}完成"

async def main():
    results = await asyncio.gather(
        fetch("新闻源A", 2),
        fetch("新闻源B", 1),
        fetch("新闻源C", 3)
    )
    print(results)

asyncio.run(main())
```

执行时：

- 三个协程都被提交给事件循环。
- 每个协程遇到 `await` 时可以暂停。
- 事件循环调度其他就绪协程。
- 所有任务完成后，`gather()` 返回结果列表。
- 默认情况下，结果顺序与传入任务的顺序一致。

**实践：**

项目中多个 RSS 新闻源之间通常没有直接依赖，可以考虑并发请求，最后汇总采集结果。

**局限与取舍：**

- 并发任务过多可能造成连接数过大、接口限流。
- 需要设置超时、异常处理和并发数量限制。
- 如果任务之间存在依赖关系，则不能简单地全部并发执行。

### 6. 阻塞操作对异步程序有什么影响？

**定义：**

阻塞操作是指当前执行流程需要等待某个操作完成，在此期间无法继续执行其他代码。

**目的：**

识别异步程序中的阻塞点，避免一个任务影响整个事件循环。

**原理：**

例如：

```python
import asyncio
import time

async def task_a():
    print("A开始")
    time.sleep(3)  # 同步阻塞
    print("A结束")

async def task_b():
    print("B开始")
    await asyncio.sleep(1)
    print("B结束")

async def main():
    await asyncio.gather(task_a(), task_b())

asyncio.run(main())
```

`time.sleep(3)` 不会让出事件循环执行权。

因此 A 执行阻塞操作时，B 也无法正常获得调度机会。

应该改成：

```python
await asyncio.sleep(3)
```

**实践：**

在项目中使用异步请求时，需要注意：

- 不要在异步函数中直接执行长时间同步阻塞操作。
- 使用异步 HTTP 客户端进行网络请求。
- 必要时将同步阻塞操作放到线程池执行。

**局限与取舍：**

- 异步库并不总是覆盖所有第三方库。
- 将同步函数放入线程池会增加线程调度开销。
- CPU 密集型任务通常更适合多进程或专门的计算任务执行方式。
