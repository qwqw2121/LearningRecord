### 1. 进程、线程、协程的区别

**定义：**
 
- 进程：操作系统进行资源分配和调度的基本单位。
- 线程：进程内部的**执行单元**，同一进程中的线程共享进程资源。
- 协程：由**程序**控制的轻量级执行单元，可以在**特定位置暂停和恢复**。

**目的：**

通过不同的并发方式提高程序执行效率：                                                 

- 进程适合 CPU 密集型任务。
- 线程适合 I/O 密集型任务。
- 协程适合大量 I/O 等待场景。

**原理：**

- 进程拥有独立的**内存空间和资源**。
- 线程共享进程内存，由操作系统调度。
- 协程通过**事件循环调度**，在遇到可等待操作时主动让出执行权。

Python 常见实现中，**线程由操作系统调度**，`asyncio` 协程主要由**事件循环调度**。
async /əˈsɪŋk/异步，非同步（asynchronous）  async io

**实践：**

AI 资讯项目中：

- RSS 请求、网络 API 调用属于 I/O 密集型操作，可以考虑并发。
- 新闻文本处理、数据清洗可以根据具体任务选择同步或并发方式。
- 如果是大量 CPU 密集型计算，可以考虑多进程。

**局限与取舍：**

- 多进程通信成本较高，内存开销较大。
- 多线程需要注意线程安全和锁竞争。
- 协程需要异步接口配合，不能自动加速同步阻塞代码。

### 2. 同步和异步的区别

**定义：**

- 同步：调用一个任务后，通常需要**等待它完成才能继续执行后续代码**。
- 异步：任务遇到等待操作时，可以**暂时让出执行权**，让其他任务继续执行。

**目的：**

提高程序在等待网络、文件、数据库等 I/O 操作时的资源利用率。

**原理：**

同步执行：

```python
import time

def task(name):
    time.sleep(2)
    print(name)

task("A")
task("B")
```

两个任务依次执行，总耗时约 4 秒。

异步执行：

```python
import asyncio

async def task(name):
    await asyncio.sleep(2)
    print(name)

async def main():
    await asyncio.gather(
        task("A"),
        task("B")
    )

asyncio.run(main())
```

**两个任务可以在等待期间交替执行**，总耗时约 2 秒。

**实践：**

项目涉及 RSS 抓取和外部模型 API 调用时，如果使用异步客户端，可以让多个 I/O 请求并发执行。

**局限与取舍：**

- 异步代码结构相对复杂。
- 同步阻塞操作可能拖住整个事件循环。
- 并不是所有任务都适合异步，简单任务使用同步方式可能更容易维护。

### 3. `async`、`await`、`asyncio`

**定义：**

- `async`异步：用于**定义协程函数**。
- `await`等待：等待一个可等待对象完成，同时允许当前协程让出执行权。
- `asyncio`：Python 标准库，提供**协程、事件循环和异步任务管理**能力。asyncio 是 Python 内置的异步 I/O 框架，可以帮助我们在等待网络请求、文件操作等任务时，不必一直阻塞程序。

**目的：**

使用协程处理 I/O 等待任务，提高并发执行效率。

**原理：**

```python
import asyncio

async def fetch_news():
    print("开始请求")
    await asyncio.sleep(2)
    print("请求完成")
    return "新闻数据"

async def main():
    result = await fetch_news()
    print(result)

asyncio.run(main())
```
asyncio.sleep(2)：创建一个等待 2 秒的异步操作。
await：等待这个异步操作完成。
异步等待本身不等于并发，只有存在其他可调度的任务时，才能体现并发效果。
调用普通函数时，函数会直接执行。调用异步函数时，默认不会立即执行函数体，而是返回一个**协程对象（Coroutine）**。

执行过程：
1. `async def` 定义协程函数。
2. 调用协程函数得到协程对象，并不会立即执行函数体。
3. `asyncio.run()` 创建并运行事件循环。
4. 事件循环调度协程执行。
5. 遇到 `await` 时，如果等待的操作尚未完成，当前协程可以暂停。
6. 等待操作完成后，协程恢复执行。
概念	含义
async	定义异步函数
await	**等待协程或其他可等待对象完成，并在等待时让出执行权**
**协程	可以暂停和恢复执行的异步任务**
Event Loop	事件循环，负责调度协程
asyncio.run()	启动并运行顶层协程
asyncio.gather()	并发调度多个协程并收集结果

**实践：**

项目中如果需要并发请求多个 RSS 源或调用多个外部 API，可以使用异步函数和异步客户端。

**局限与取舍：**

- `await` 只能用于协程函数等合法的异步上下文。
- 普通同步函数不能直接通过 `await` 等待。
- 异步函数内部仍然执行同步阻塞操作时，可能阻塞事件循环。

### 4. 事件循环是什么？

**定义：**

事件循环是 asyncio 的核心调度机制，负责**管理和调度协程任务**。

**目的：**

让多个协程在 I/O 等待期间交替执行，避免程序一直等待某一个任务完成。

**原理：**

事件循环大致执行以下过程：

1. 获取可运行的协程任务。
2. 调度协程向下执行。
3. 遇到 `await` 等待尚未完成的 I/O 操作时，暂停当前协程。
4. 继续执行其他就绪任务。
5. 等待的 I/O 操作完成后，将对应协程重新加入可运行队列。
6. 继续调度，直到任务完成。

**实践：**

在异步请求新闻源时，一个请求等待网络响应，事件循环可以调度其他请求继续执行。

**局限与取舍：**

- 一个事件循环中，阻塞操作会影响其他协程的执行。
- **CPU 密集型计算不适合**直接长时间运行在事件循环中。
- 可以通过线程池或进程池处理不适合直接在事件循环中执行的任务。

### 5. `asyncio.gather()` 如何实现并发？

**定义：**

`asyncio.gather()` 用于**并发调度多个可等待对象**，并在它们完成后收集结果。

**目的：**

当多个任务相互独立时，同时发起执行，减少整体等待时间。

**原理：**

```python
import asyncio

async def fetch(name, delay):
    await asyncio.sleep(delay)
    return f"{name}完成"

async def main():
    results = await asyncio.gather(
        fetch("新闻源A", 2),
        fetch("新闻源B", 1),
        fetch("新闻源C", 3)
    )
    print(results)

asyncio.run(main())
```

执行时：

- 三个协程都被提交给事件循环。
- 每个协程遇到 `await` 时可以暂停。
- 事件循环调度其他就绪协程。
- 所有任务完成后，`gather()` 返回结果列表。
- 默认情况下，结果顺序与传入任务的顺序一致。

**实践：**

项目中多个 RSS 新闻源之间通常没有直接依赖，可以考虑并发请求，最后汇总采集结果。

**局限与取舍：**

- 并发任务过多可能造成连接数过大、接口限流。
- 需要设置**超时、异常处理和并发数量**限制。
- 如果任务之间存在**依赖关系**，则不能简单地全部并发执行。

### 6. 阻塞操作对异步程序有什么影响？

**定义：**

阻塞操作是指**当前执行流程需要等待某个操作完成**，在此期间无法继续执行其他代码。

**目的：**

识别异步程序中的阻塞点，避免一个任务影响整个事件循环。

**原理：**

例如：

```python
import asyncio
import time

async def task_a():
    print("A开始")
    time.sleep(3)  # 同步阻塞
    print("A结束")

async def task_b():
    print("B开始")
    await asyncio.sleep(1)
    print("B结束")

async def main():
    await asyncio.gather(task_a(), task_b())

asyncio.run(main())
```

`time.sleep(3)` 不会让出事件循环执行权。

因此 A 执行阻塞操作时，B 也无法正常获得调度机会。

应该改成：

```python
await asyncio.sleep(3)
```

**实践：**

在项目中使用异步请求时，需要注意：

- 不要在异步函数中直接执行**长时间同步阻塞**操作。
- 使用异步 HTTP 客户端进行网络请求。
- 必要时将同步阻塞操作放到线程池执行。

**局限与取舍：**

- 异步库并不总是覆盖所有第三方库。
- 将同步函数放入线程池会增加线程调度开销。
- CPU 密集型任务通常更适合多进程或专门的计算任务执行方式。

### 7. 什么是 I/O 密集型任务？

**定义：**

I/O 密集型任务（I/O Bound Task）是指程序的运行效率主要受**输入/输出（Input/Output）操作限制**，而不是受CPU（中央处理器）计算能力限制。

简单来说，就是程序大部分时间在等待，而不是在计算。

**常见场景：**
- 网络请求：请求新闻网站、调用 LLM API。
- 文件操作：读取、写入文件。
- 数据库操作：查询、写入数据库。

**目的：**

理解不同任务的性能瓶颈，选择合适的并发方式，提高程序运行效率。

**原理：**

例如，调用 LLM API：

```python
import time

def analyze_news():
    print("开始调用 API")
    time.sleep(2)  # 模拟网络等待
    print("API 返回结果")
```

程序调用 API 后，需要等待服务器处理并返回结果。

这段时间 CPU 通常不需要持续计算，因此可以利用等待时间处理其他任务。

对于 I/O 密集型任务：
- 多线程：一个线程等待时，其他线程可以执行。
- 异步编程：一个协程等待时，事件循环可以调度其他协程。

**实践：**

在 AI 资讯项目中：

- `article_extractor.py`：抓取网页正文，主要受**网络 I/O **影响。
- `news_analyzer.py`：调用 LLM API，主要受**网络请求和模型响应时间**影响。

这两类任务都属于**典型的 I/O 密集型任务**，适合使用**并发**提高处理效率。

**局限与取舍：**

- I/O 密集型任务适合多线程或异步，并不意味着并发越多越好。
- 并发数量过大可能导致 API 限流、连接耗尽或服务器压力增加。
- 需要结合**超时、重试、限流和异常处理设计并发策略**。
- 如果任务主要消耗 CPU 进行计算，则不一定适合使用多线程。


###  8. 并发和并行有什么区别？

**定义：**

- **并发（Concurrency）：** 多个任务在**一段时间内交替执行或重叠推进**，不要求同一时刻执行。
- **并行（Parallelism）：** 多个任务在**同一时刻真正同时执行**，通常需要多个 CPU 核心或其他并行计算资源。

简单来说：

并发强调多个任务都能推进，并行强调多个任务同时执行。

**目的：**

理解任务执行方式，选择合适的技术提高程序处理效率。

**原理：**

并发：

例如，单核 CPU 执行两个任务：

```text
时间轴 →

任务 A：执行 → 等待 → 执行
任务 B：       执行 → 等待 → 执行
```

任务通过交替执行或等待时间重叠，让多个任务都能推进。

并行：

例如，双核 CPU 执行两个任务：

```text
CPU 核心 1：任务 A 持续执行
CPU 核心 2：任务 B 同时执行
```

两个任务在同一时刻占用不同计算资源。

**实践：**

AI 资讯项目中的线程池：

两个模块都使用 `ThreadPoolExecutor` 创建线程池，将新闻处理拆分为独立任务，由多个线程并发执行，提高 I/O 密集型任务的处理效率。

- `article_extractor.py`：线程池并发抓取网页正文。
- `news_analyzer.py`：线程池并发调用 LLM API。

执行过程：

```text
正文提取：线程 → 下载网页 → 提取正文
LLM 分析：线程 → 调用 LLM API → 解析 JSON
```
这里主要实现的是**多线程并发**，而不是 CPU 密集型计算的真正并行。

为什么用多线程没用异步呢？
这两个模块的核心操作都是 调用现有的**同步函数**执行 I/O 操作，所以使用 ThreadPoolExecutor 多线程线程池是一种比较直接、合适的方案。
并不是 I/O 密集型任务就必须使用 asyncio。多线程和异步都是解决 I/O 等待问题的方式，只是实现机制不同

指数退避（Exponential Backoff）。

等待时间按照指数增长：t=2^{attempt}
**局限与取舍：**

- 多线程适合 I/O 密集型任务，但受 Python GIL 影响，CPU 密集型 Python 代码通常无法通过多线程实现真正的多核并行。
- 多进程可以利用多个 CPU 核心实现并行，但进程创建、通信和数据传递有额外开销。
- asyncio 通过事件循环调度协程，适合大量 I/O 等待任务，但**单个事件循环中的协程通常在同一线程内**交替执行。
- 具体采用多线程、异步还是多进程，需要根据任务类型、第三方库支持和资源开销决定。

| 类型 | 重点 | 常见技术 |
|---|---|---|
| 并发 | 多个任务交替或重叠推进 | 多线程、异步、协程 |
| 并行 | 多个任务同时占用计算资源执行 | 多进程、多核 CPU、GPU、分布式计算 |

1. 进程、线程、协程分别是什么？它们在资源占用和任务切换方面有什么区别
   进程（Process）：操作系统进行**资源分配和管理的基本单位**。每个进程拥有相对独立的内存空间和系统资源。**进程之间相互隔离**，通信通常需要 IPC（进程间通信）。
   线程（Thread）: **进程内部的执行单元**，操作系统进行** CPU 调度的基本单位**。线程属于进程，一个进程可以包含多个线程。同一进程中的线程共享进程的内存和资源，但每个线程拥有自己的栈和执行状态。
   协程（Coroutine）：一种用户态的轻量级**执行单元**，可以在执行过程中**主动暂停和恢复**。协程通常由程序或运行时调度，不需要像线程那样频繁依赖操作系统进行上下文切换。
   
| 对比     | 进程       | 线程         | 协程                 |
| -------- | ---------- | ------------ | -------------------- |
| 所属层面 | 操作系统   | 操作系统     | 程序运行时           |
| 资源占用 | 较大       | 较小         | 通常较小             |
| 内存空间 | 相互独立   | 同进程内共享 | 通常共享所在进程内存 |
| 切换成本 | 较高       | 相对较高     | 通常较低             |
| 调度方式 | 操作系统   | 操作系统     | 协作式调度为主       |
| 典型场景 | 多进程计算 | I/O 并发     | 大量异步 I/O         |

2. async 和 await 到底改变了函数的什么执行行为？
   资源的占有，await可以暂时放弃执行权
   async 用于定义异步函数，await 用于等待异步操作完成。两者配合可以让程序在等待 I/O 时释放执行权，提高任务并发处理效率。
async：用于定义异步函数。调用异步函数时，默认不会立即执行函数体，而是返回一个协程对象。
await：用于等待一个可等待对象完成。在等待期间，当前协程会挂起并让出执行权，事件循环可以调度其他协程。

3. 事件循环如何调度多个协程？一个协程执行到 await 后发生了什么？
   事件循环**负责管理协程的执行**。当协程执行到 await 并等待异步操作时，会**暂时挂起**，将执行权交还给事件循环。事件循环可以继续调度其他就绪任务，等原任务等待的操作完成后再恢复执行。
   事件循环（Event Loop）：负责管理和调度异步任务的核心机制。
基本过程：

   1. 将协程注册到事件循环。
   2. 事件循环选择一个可以执行的协程。
   3. 协程执行到 await，遇到需要等待的操作。
   4. 当前协程挂起，事件循环继续调度其他就绪的协程。
   5. 等待的操作完成后，原协程恢复执行。
   6. 所有任务完成后，事件循环结束。
   
4. 为什么在异步函数中调用 time.sleep() 会阻塞其他协程？
   因为程序不会停止，产生同步阻塞
   time.sleep() 是同步阻塞操作，即使在 async 函数中调用它，也不会自动变成异步操作。
   
5. asyncio.gather() 如何并发执行多个协程？其中一个任务异常时，其他任务会怎样？
   
   gather 可以并发调度多个协程，并收集执行结果，返回顺序与传入顺序一致。默认情况下，一个任务异常会向调用者传播，但不会自动取消其他任务。设置 return_exceptions=True 可以将异常作为结果收集。
  
   asyncio.gather() 用于并发调度多个可等待对象，并等待它们全部完成。

6. Python 的 GIL 对**多线程执行 CPU 密集型任务**有什么影响？
   
  GIL 限制了传统 CPython 中多个线程同时执行 Python 字节码，因此多线程适合 I/O 密集型任务，而 **CPU 密集型任务通常更适合多进程**，利用多个 CPU 核心实现真正的并行计算。
   
GIL（Global Interpreter Lock，全局解释器锁）是 CPython 解释器中的一把全局锁。
原理：在传统的 CPython GIL 模式下，**同一时刻通常只有一个线程能够执行 Python 字节码**。
 - I/O 密集型任务：线程等待网络或文件操作时可以释放 GIL，其他线程有机会执行，因此多线程能够提高效率。
 - CPU 密集型任务：多个线程竞争 GIL，通常不能利用多个 CPU 核心同时执行 Python 字节码，因此多线程的性能提升有限，有时反而会增加线程切换开销。

CPU 密集型任务通常考虑：
 - 多进程：每个进程拥有独立的解释器和 GIL，可以利用多个 CPU 核心。
 - 进程池：通过 ProcessPoolExecutor 管理多个进程。
 - GPU：适合能够利用 GPU 并行计算的任务。


**需要面试前回顾的内容：**
- 同步、异步、并发、并行的区别。

- 进程、线程、协程的区别和适用场景。

- async、await 和事件循环的基本执行过程。

- asyncio.gather() 的作用，以及返回结果的顺序。
  
asyncio.gather() 用于并发调度多个可等待对象，并等待它们全部完成。
返回结果是一个列表，**顺序与传入的协程顺序一致**，而不是按照任务完成顺序排列。

- 为什么 I/O 密集型任务适合使用异步，而 CPU 密集型任务通常需要考虑多进程或进程池。
  
  I/O 密集型任务的瓶颈是等待，CPU 密集型任务的瓶颈是计算
I/O 密集型任务的主要瓶颈是网络请求、文件读写等 I/O 等待，而不是 CPU 计算。使用异步编程时，一个协程遇到 await 等待网络响应，可以暂时让出执行权，由事件循环调度其他协程，从而充分利用等待时间，提高并发处理效率。

 CPU 密集型任务主要消耗 CPU 进行计算，没有明显的 I/O 等待，异步编程无法自动提高计算速度。另外，传统 CPython 中存在 GIL，限制多个线程同时执行 Python 字节码，因此通常使用多进程或进程池，利用多个 CPU 核心实现真正的并行计算。

最后记住一句话：
  - I/O 密集型：任务在等，利用等待时间做其他事，所以适合异步或多线程。
  - CPU 密集型：任务在算，需要更多计算资源，所以通常考虑多进程
