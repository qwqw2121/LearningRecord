## 一、学习内容与记录

### 1. Embedding 是什么？为什么要把文本转换成向量？

**定义：**

Embedding（嵌入）是将文本、图片等数据转换为固定维度的数值向量的过程。

对于文本 Embedding，模型会将一段文本转换为一个向量，使语义相近的文本在向量空间中具有较高的相似度。

例如：

```text
文本A：人工智能正在快速发展
文本B：AI技术发展速度很快
```

经过 Embedding 模型处理后，得到两个数值向量：

```python
vector_a = [0.12, -0.35, 0.68, ...]
vector_b = [0.15, -0.31, 0.65, ...]
```

实际向量通常包含更多维度。

**目的：**

计算机无法直接**按照人的语义理解文本**。

将文本转换为向量后，可以通过**数学方法计算文本之间的相似程度**，从而实现**语义检索**。

例如用户搜索：

```text
大模型在医疗行业的应用
```

即使新闻标题没有出现完全相同的关键词，也可能检索到语义相关的新闻。

**原理：**

Embedding 模型通过大量文本数据训练，学习文本与语义表示之间的关系。

大致过程：

1. 输入文本。
2. 模型进行 Tokenization，将文本转换为 Token。
3. Token 经过模型的神经网络计算。
4. 模型生成文本的向量表示。
5. 输出固定维度的浮点数向量。
需要注意：Embedding 并不是简单地给每个词分配一个固定数字，而是通过训练得到能够表达上下文语义的向量表示。

# Embedding 模型的处理流程

Embedding 的作用：**将文本转换成固定维度的浮点数向量**，使计算机能够通过向量计算判断文本之间的语义相似度。

## 整体流程

```
输入文本
   ↓
Tokenization（文本切分）
   ↓
Token ID（转换为数字编号）
   ↓
Embedding Layer（初始向量映射）
   ↓
Transformer（上下文语义计算）
   ↓
Pooling（向量聚合）
   ↓
输出文本 Embedding
```
模型根据训练阶段学到的参数，把输入文本映射到向量空间中的一个位置。
## 每一步实现什么

1. 输入文本（Input Text）
   - 接收需要向量化的文本。
   - 作为 Embedding 模型的输入。
2. Tokenization（文本切分）         #Tokenizer 负责文本切分和 ID 映射，尚未生成最终文本向量。
   - 将文本切分成 Token。          
   - 将每个 Token 转换成对应的 Token ID。
3. Embedding Layer（初始向量映射）
   - 根据 Token ID 查找对应的向量。
   - 将离散的数字编号转换成连续的向量表示。
4. Transformer（上下文语义计算）  
   - 通过 Self-Attention 机制计算 Token 之间的关联。
   - 结合上下文信息，生成具有语义信息的 Token 表示。
5. Pooling（向量聚合）
   - 将多个 Token 的向量进行聚合。
   - 将 Token 级别的向量转换为文本级别的向量。
6. 输出 Embedding
   - 输出固定维度的浮点数向量。
   - 用于向量存储、相似度计算和语义检索。
核心区别： Token Embedding 是 Token 级别的初始向量表示；Text Embedding 是经过模型计算和聚合后得到的整段文本向量。

1. Tokenization 的主要作用是什么？ 将文本切分为 Token，并映射为 Token ID
2.  为什么 Token 经过 Transformer 后，语义表示会发生变化？
Self-Attention 让 Token 能结合其他 Token 的信息，形成上下文相关的表示。
3. 经过 Transformer 后，为什么还需要 Pooling？
Pooling 将 Token 级表示转换成句子或文本级表示，供向量检索使用。

Token 和 Token ID 不一样。
- Token：文本切分后的基本单位。
- Token ID：Token 在模型词表中对应的整数编号。
- 
- "Embedding 模型在训练阶段通过大量文本学习语义关系，并将这些规律保存在模型参数中。实际使用时，输入文本经过 Transformer 等网络计算，模型根据已经学习到的参数生成对应的向量，使语义相近的文本在向量空间中更接近。"

- "Embedding Layer 根据 Token ID 查找初始向量，Transformer 通过 Self-Attention 计算 Token 之间的上下文关系，并结合上下文更新 Token 向量，使其包含当前语境下的语义信息。"
- 
2+3: 新文本经过 Tokenization 后得到的 Token ID，可以在**模型的 Embedding 矩阵中找到对应的初始向量**。
因为 Tokenizer 使用的是模型规定的词表（Vocabulary），而 Embedding 矩阵也是按照这个词表建立的，所以 Token ID 和向量是一一对应的。
记住三个概念：
- Token：文本切分后的基本单位。
- Token ID：Token 对应的数字编号。
- 初始向量：根据 Token ID 从 Embedding 矩阵中查找到的向量。
注意：这里的“新文本”可以是模型从未见过的句子，但其中的 Token 必须属于模型词表
输入文本经过 Tokenization 时，已经保留了 Token 的顺序。
4.Transformer 的作用是：
- 通过 Self-Attention 计算不同 Token 之间的关联。
- 结合其他 Token 的上下文信息，更新每个 Token 的向量表示。
- 最终得到**一组包含上下文语义信息的 Token 向量**。
**Transformer 会在初始 Token 向量的基础上，结合上下文信息进行计算，生成新的 Token 向量，因此具体的向量数值会发生变化**。
5.Pooling 就是把 Transformer 输出的多个 Token 向量聚合成**一个固定维度的向量**，这个向量就是整段文本的 Embedding。
   1. Embedding Layer：每个 Token ID 查找对应的初始向量。
   2. Transformer：结合上下文，更新每个 Token 的向量数值。
   3. Pooling：将多个 Token 向量聚合成一个文本向量。

**实践：**

AI 资讯项目使用阿里云 DashScope 的 `text-embedding-v3` 模型，将新闻文本转换为向量。

简化示例：

```python
import dashscope
response = dashscope.TextEmbedding.call(
    model="text-embedding-v3",
    input=["人工智能正在快速发展"]
)
vector = response.output["embeddings"][0]["embedding"]

print(len(vector))
print(vector[:5])
```

实际调用需要配置 API Key，并处理接口错误、批量请求和返回结果。

**局限与取舍：**

Embedding 可以**提高语义检索能力**，但不代表**模型完全理解了文本**。

局限：
- 语义相近不一定代表事实相关。
- 专业领域术语可能存在理解偏差 。
- 长文本可能受到模型输入长度限制。
- Embedding 模型不同，向量空间通常不能直接混用。

### 2. 向量维度代表什么？

**定义：**

向量维度是一个向量包含的**数值数量**。

例如：

```python
vector = [0.1, 0.2, 0.3, 0.4]
```

这个向量的维度是 4。

**目的：**

**向量维度决定了文本表示的空间大小**，也是向量数据库存储和检索时需要遵守的重要参数。

**原理：**

Embedding 模型输出的每个维度都是模型学习得到的数值特征。

这些维度通常不能直接解释为某个明确的人工概念，例如“第 1 维代表科技，第 2 维代表医疗”。

模型通过训练，**让向量整体能够表达文本语义关系**。

不同模型可能输出不同维度的向量。

**实践：**

项目中可以查看 Embedding 输出的维度：

```python
vector = embedding_model.embed_query(
    "人工智能新闻"
)

print(len(vector))
#"text-embedding-v4"
# 1024
# [-0.08070988208055496, 0.012314791791141033, 0.06889203935861588, 0.013853290118277073, -0.011232397519052029]
```
text-embedding-v3 的默认维度也是 1024。
text-embedding-v4 默认输出 1024 维
Chroma Collection 创建后，写入的向量维度需要保持一致。

如果**模型输出维度**发生变化，通常需要**重新创建或迁移向量集合**，并重新生成 Embedding。

**局限与取舍：**

维度越高不一定意味着检索效果越好。

较高维度可能带来：
- 更多存储空间。
- 更高的计算成本。
- 更大的检索资源消耗。

具体维度需要结合模型效果、数据规模和检索需求选择。

### 3. 余弦相似度、欧氏距离、内积

**定义：**

这三种方法都可以用于衡量向量之间的关系。

1. 余弦相似度：计算两个向量**夹角的余弦值**。
2. 欧氏距离：计算两个向量**在空间中的直线距离**。
3. 内积：**对应位置元素相乘后求和**。

**目的：**

将向量之间的关系转化为可以计算的数值，从而实现相似度排序和向量检索。

**原理：**

$$
余弦相似度：
\operatorname{cos}(A,B)=

\frac{A\cdot B}{\|A\|\|B\|}
$$
取值通常在 -1 到 1 之间，越接近 1 表示方向越接近。
$$
欧氏距离：d(A,B)=\sqrt{\sum_{i=1}^{n}(A_i-B_i)^2}
$$
距离越小，两个向量越接近。
$$
内积：A\cdot B=\sum_{i=1}^{n}A_iB_i
$$

内积越大，数值越大，但它同时受到向量方向和长度影响。

**实践：**

Python 示例：

```python
import numpy as np

a = np.array([1, 2, 3])
b = np.array([2, 3, 4])

# 余弦相似度
cosine = np.dot(a, b) / (
    np.linalg.norm(a) * np.linalg.norm(b)
)

# 欧氏距离
euclidean = np.linalg.norm(a - b)

# 内积
dot_product = np.dot(a, b)

print("余弦相似度:", cosine)
print("欧氏距离:", euclidean)
print("内积:", dot_product)
```

**局限与取舍：**

不同距离度量适合不同场景：

- **余弦相似度主要关注方向**，对向量长度不敏感。
- **欧氏距离同时考虑方向和长度**。
- 内积会受到向量模长影响。

如果向量都**进行了 L2 归一化**，余弦相似度、内积和欧氏距离之间存在确定的数学关系。

实际使用时，需要确认 Embedding 模型和向量数据库使用的距离度量是否匹配。

### 4. 向量数据库与传统关系型数据库的区别

**定义：**

**关系型数据库**主要用于存储**结构化数据**，通过 SQL 和字段条件查询数据。

向量数据库主要用于存储**向量及其元数据**，并根据向量之间的**距离或相似度**进行近邻检索。

**目的：**

关系型数据库适合**精确查询**：

```sql
SELECT * FROM news
WHERE category = 'LLM';
```

向量数据库适合**语义查询**：

```text
查找与“大模型在金融行业的应用”语义相近的新闻。
```

**原理：**

关系型数据库主要根据**字段、索引和 SQL 条件**查找记录。

向量数据库通常通过**向量索引**和**近似最近邻搜索（ANN）**提高高维向量检索效率。

检索时：
1. 将用户问题转换为向量。
2. 在向量集合中查找距离较近的向量。
3. 返回对应的文本和元数据。

**实践：**

项目中采用 SQLite + Chroma：

| 数据库 | 主要职责 |
|---|---|
| SQLite | 新闻正文、标题、分类、摘要、日报、状态等结构化数据 |
| Chroma | 新闻 Embedding、关联文本和元数据，支持语义检索 |

两者不是互相替代的关系，而是承担不同职责。

**局限与取舍：**

关系型数据库：
- 精确条件查询能力强。
- 适合结构化业务数据。
- 不擅长直接进行语义相似度检索。

向量数据库：
- 适合语义相似度检索。
- 需要额外生成和维护 Embedding。
- 不适合替代关系型数据库处理复杂业务事务和关联查询。

### 5. Chroma 如何存储和检索向量？

**定义：**

Chroma 是一个向量数据库，可以存储 Embedding、文本和元数据，并支持相似度检索。

**目的：**

在 RAG 系统中，需要将**文档向量化并持久化保存**，以便后续根据用户问题检索相关内容。

**原理：**

Chroma 的 Collection 可以保存：

- `ids`：每条记录的唯一标识。
- `embeddings`：文本向量。
- `documents`：关联文本。
- `metadatas`：关联元数据。

写入示例：

```python
import chromadb

client = chromadb.PersistentClient(
    path="storage/chroma"
)

collection = client.get_or_create_collection(
    name="news"
)

collection.add(
    ids=["news_1"],
    documents=["人工智能正在快速发展"],
    embeddings=[[0.1, 0.2, 0.3]],
    metadatas=[{"category": "LLM"}]
)
```

检索示例：

```python
results = collection.query(
    query_embeddings=[[0.1, 0.2, 0.3]],
    n_results=5
)

print(results["documents"])
print(results["distances"])
```

实际使用时，查询向量与集合中已有向量必须具有相同维度。

**实践：**

项目使用 Chroma **持久化保存新闻向量**。

大致流程：

1. 从 SQLite 获取需要进行 Embedding 的新闻。
2. 调用 DashScope `text-embedding-v3` 生成向量。
3. 将向量、新闻标识、文本和元数据写入 Chroma。
4. 用户提问时生成 Query Embedding。
5. Chroma 根据向量相似度返回相关新闻。

**局限与取舍：**

Chroma 使用方便，适合**个人项目和中小规模 RAG 应用**。

需要注意：
- 向量维度必须一致。
- 重复 ID 写入需要考虑更新策略。
- 向量数据与 SQLite 之间需要维护关联关系。
- 数据量增大后，需要评估索引、并发和部署能力。

### 6. Top-K 是什么？

**定义：**

Top-K 表示**从检索结果中选出排名靠前的 K 条数据**。

例如 Top-5 就是返回最相关的 5 条结果。

**目的：**

RAG 不需要把全部文档都交给 LLM，而是先检索出与问题最相关的一部分内容，减少上下文长度和模型调用成本。

**原理：**

假设用户查询：

```text
大模型在医疗领域有哪些应用？
```

向量数据库计算查询向量与新闻向量之间的距离，然后根据距离或相似度排序，返回前 K 条结果。

对于距离度量，通常是距离越小越接近；对于相似度度量，通常是相似度越高越相关。

**实践：**

Chroma 示例：

```python
results = collection.query(
    query_embeddings=[query_vector],
    n_results=5
)
```

这里的 `n_results=5` 就表示返回 Top-5。

项目中需要根据检索效果调整 K，并观察返回新闻是否真正与问题相关。

**局限与取舍：**

K 太小：
- 可能遗漏重要信息。
- 召回率不足。

K 太大：
- 会引入无关内容。
- 增加上下文长度和模型成本。
- 可能干扰 LLM 生成。

K 需要通过检索评估确定，而不是越大越好。

### 三、学习复盘

**今天还没搞懂的内容：**

- Embedding 模型是如何把一段文本转换成固定维度的向量的？向量中的每个数字具体代表什么？
  mbedding 模型先将文本切分为 Token，再转换为 Token ID，经过神经网络提取上下文语义特征，最后通过 Pooling 等方式聚合成固定维度的向量。
  每个数字是模型学习到的一个语义特征维度上的数值，多个数字共同构成文本的语义表示。单个数字通常没有明确、独立的人类可解释含义。

- 为什么语义相近的两段文本，在向量空间中通常也比较接近
  因为 Embedding 模型在**训练过程中学习文本之间的语义关系**，使语义相近的文本在向量空间中的表示更加接近，语义不同的文本表示相对远离。
  因此，可以通过向量相似度计算进行语义检索。

- 为什么不同 Embedding 模型生成的向量不能直接混合检索？
  不同模型的训练数据、网络结构、向量维度和语义空间可能不同。
  即使两个模型生成的向量维度相同，也不代表它们的每个维度具有相同含义。
  因此，不能直接混合比较。通常需要使用同一个 Embedding 模型生成文档向量和查询向量。

- 余弦相似度、欧氏距离和内积之间有什么关系？向量归一化会产生什么影响？
  归一化后：
  - 内积等于余弦相似度。
  - 欧氏距离与余弦相似度可以相互转换。
  - 可以减少向量长度对比较结果的影响。
- 
- Chroma 如何根据查询向量找到最相似的向量？它使用精确搜索还是近似最近邻搜索？
  Chroma 根据查询向量和已存储向量计算距离，找到最接近的 Top-K 结果。配置了余弦距离，并使用 Chroma 的 HNSW 索引进行向量检索。
  HNSW 属于**近似最近邻（ANN）搜索算法**，主要目的是提高**大规模向量检索效率**，不保证每次都找到数学意义上的绝对精确最近

- Chroma 返回的 `distances` 到底代表距离还是相似度？数值越大是否意味着越相关？
  distances 表示距离，不是相似度。距离越小，越相似。

- 如果 Embedding 模型升级或向量维度改变，原有 Chroma 数据应该如何处理？
  建议重新生成向量，而不是直接把新旧向量混合。
    处理步骤：
    1. 确定新 Embedding 模型和向量维度。
    2. 使用新模型重新计算所有新闻的 Embedding。
    3. 创建新的 Chroma Collection 或新的向量存储。
    4. 将新向量重新写入。
    5. 验证检索结果。
    6. 切换到新的向量库，确认正常后再处理旧数据。

**需要面试前回顾的内容：**

- Embedding 的定义、作用和基本生成过程。
  Embedding 是将文本转换成固定维度的浮点数向量，用于表示文本的语义信息。
  主要用于语义检索、文本相似度计算和 RAG 知识召回。

- 向量维度的含义，以及维度变化对存储和检索的影响。
  向量维度表示模型用多少个数值共同表示一段文本。
  维度越高，存储和计算成本通常越大，但不代表语义表达能力一定越好。
  维度变化会影响向量存储结构和检索计算，通常需要重新生成向量。

- 余弦相似度、欧氏距离、内积的计算方式和适用场景。
    余弦相似度：比较向量方向，常用于文本语义检索。
    欧氏距离：计算两个向量之间的直线距离。
    内积：计算对应维度乘积之和，同时受到方向和长度影响。

- 关系型数据库与向量数据库的区别，为什么项目同时使用 SQLite 和 Chroma。

- Chroma 的 Collection、ID、Embedding、Document 和 Metadata 分别是什么。
    Collection	向量集合，类似数据表
    ID	每条向量记录的唯一标识
    Embedding	文本对应的向量
    Document	生成向量时使用的原始文本
    Metadata	新闻标题、来源、分类、发布时间等附加信息

- 从新闻文本到 DashScope `text-embedding-v3` 向量，再到 Chroma 持久化存储的完整过程。
    1. 项目首先从 SQLite 中读取已经完成分析、等待向量化的新闻，提取标题、摘要、分类和关键词，拼接成待向量化文本。
    2. 然后调用 DashScope 的 text-embedding-v3 模型，将新闻文本转换成固定维度的 Embedding 向量。
    3. 最后调用 Chroma 的 upsert 方法，将新闻 ID、Embedding 向量、原始文本和 Metadata 一起保存到 Collection 中。同时更新 SQLite 中的新闻处理状态为 embedded。
    4. 其中，SQLite 负责保存新闻业务数据和处理状态，Chroma 负责保存向量及相关文本信息，支持后续语义检索。

- 用户问题如何生成 Query Embedding，并通过 Chroma 检索 Top-K 新闻。
  用户输入问题后，系统调用与新闻入库时相同的 Embedding 模型，将用户问题转换成向量。然后将这个查询向量传给 Chroma，Chroma 根据配置的余弦距离，计算查询向量与新闻向量之间的距离，找出距离较小、语义更接近的新闻，返回 Top-K 条结果。Agent 再根据检索结果进行后续处理，例如整理新闻内容并生成回答。

  用户问题会先经过与新闻向量化相同的 Embedding 模型转换成查询向量，再通过 Chroma 进行向量相似度检索，召回语义相关的新闻，供 Agent 后续使用。

- 如果检索结果不相关，应该优先排查 Embedding、距离度量、数据质量还是 Top-K 设置？
    数据质量：新闻文本是否完整，标题、摘要、关键词是否准确。
    Embedding 模型：文档向量和查询向量是否使用同一个模型。
    距离度量：是否使用了正确的距离计算方式。
    Top-K 设置：召回数量是否太少，是否漏掉相关内容。
    重排序：是否需要增加 Rerank，提高候选结果的相关性。
