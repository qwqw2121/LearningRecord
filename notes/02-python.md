## 一、学习内容与记录

### 1. list、tuple、dict、set

**定义：**

Python 常用的四种内置数据结构：

| 类型 | 特点 | 示例 |
|---|---|---|
| list列表 | 有序、可变、允许重复 | `[1, 2, 3]` |
| tuple元组 | 有序、不可变、允许重复 | `(1, 2, 3)` |
| dict字典 | 键值对、键唯一 | `{"id": 1}` |
| set集合 | 元素唯一、无序 | `{1, 2, 3}` |

列表和元组的“可变/不可变”，指的是对象创建后，能不能在**原对象上修改它的内容**。注意是“原对象上改”，不是“重新赋值让变量指向新对象”
**目的：**

- list：保存多个数据，方便遍历、添加和删除。
- tuple：保存一组不需要修改的数据。
- dict：通过键获取对应的值，适合组织**结构化数据**。
- set：去重、快速判断元素是否存在、集合运算。

**原理：**

- list：底层是**动态数组**，支持通过**索引访问**，添加元素时可能触发扩容。
- tuple：底层也是连续存储的元素引用，但创建后不能修改元素引用。
- dict：基于哈希表实现，通过 key 的哈希值定位存储位置。{key:value}
- set：本质上也是基于哈希表实现，只保存唯一元素。

**实践：**

```python
# list：保存新闻标题
news = ["OpenAI发布新模型", "Google发布新模型"]
news.append("DeepSeek发布新模型")

# tuple：保存固定配置
config = ("text-embedding-v3", 1024)

# dict：保存新闻信息
article = {
    "title": "AI行业新闻",
    "category": "LLM",
    "importance": 8
}
print(article["title"])

# set：新闻标签去重
tags = ["LLM", "RAG", "LLM", "Agent"]
unique_tags = set(tags)
```

项目中可以用 dict 表示一条新闻记录，用 list 保存新闻集合，用 set 进行标签或 ID 去重。

**局限与取舍：**

- list 查询元素是否存在通常需要 O(n)。
- tuple 不支持修改，不适合需要频繁更新的数据。
- dict 的 key 必须是可哈希对象，通常使用不可变类型。
- set 不保留业务所需的稳定顺序，不能通过索引访问。

根据数据用途选择，而不是所有数据都使用 list。

### 2. 可变对象与不可变对象

**定义：**

- 可变对象：**创建后可以修改内部内容**，例如 list、dict、set。
- 不可变对象：**创建后不能原地修改**，例如 int、str、tuple。

**目的：**

理解对象修改、变量引用、函数参数传递时的行为，避免意外修改共享数据。

**原理：**

Python 变量保存的是对象的引用。

```python
a = [1, 2]
b = a  

b.append(3)

print(a)  # [1, 2, 3]
```
b = a 不是复制列表，而是让** b 和 a 指向同一个列表对象**
a 和 b 指向同一个 list，因此通过 b 修改后，a 看到的内容也发生变化。

不可变对象修改时，通常会创建新的对象或产生新的引用绑定。

**实践：**

```python
def add_tag(tags):
    tags.append("RAG")

news_tags = ["LLM"]
add_tag(news_tags)

print(news_tags)  # ['LLM', 'RAG']
```

项目处理新闻数据时，如果**多个函数共享同一个 dict 或 list**，需要注意是否会修改原始数据。

**局限与取舍：**

可变对象使用方便，但共享引用可能造成意外修改；不可变对象更容易保证数据稳定，但修改时需要创建新对象。

### 3. 深拷贝与浅拷贝

**定义：**

- 浅拷贝：创建一个新的外层对象，但**内部嵌套对象仍然共享引用**。
- 深拷贝：**递归复制对象及其内部嵌套对象**。

**目的：**

在修改数据时，避免意外影响原始对象。

**原理：**

```python
import copy

data = {
    "title": "AI新闻",
    "tags": ["LLM", "RAG"]
}

shallow = copy.copy(data)
deep = copy.deepcopy(data)

shallow["tags"].append("Agent")

print(data["tags"])  # ['LLM', 'RAG', 'Agent']
print(deep["tags"])  # ['LLM', 'RAG']
```

浅拷贝只复制外层 dict，内部 tags 列表仍然共享。

深拷贝会递归复制**嵌套列表**，因此修改副本不会影响原始数据。

**实践：**

在处理新闻数据时，如果需要基于原始数据生成一份可独立修改的副本，可以考虑使用深拷贝。

**局限与取舍：**

深拷贝需要更多时间和内存，而且某些对象不适合直接复制。浅拷贝成本较低，如果只需要复制外层结构，优先考虑浅拷贝。

### 4. 装饰器

**定义：**

装饰器本质上是一个**接收函数并返回函数的高阶函数**，可以在不修改原函数代码的情况下增加功能。
**装饰器语法会把装饰器返回值重新绑定到原函数名。**
**目的：**

实现日志记录、执行时间统计、权限校验等通用功能，减少重复代码。

**原理：**

**Python 中函数也是对象，可以作为参数传递和作为返回值。**

装饰器通常通过**闭包保存原函数**，再返回一个包装函数。

```python
import time
from functools import wraps

def timer(func):
    @wraps(func)  #主要作用是保留原函数的元信息，比如函数名称、文档字符串。否则，装饰后的 process_news 实际指向 wrapper，函数名称等信息也会变成 wrapper。
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)#这行是整个装饰器真正执行原函数的地方
        print(f"耗时: {time.time() - start:.4f}s")
        return result
    return wrapper

@timer
def process_news(count):
    time.sleep(1)
    return count

process_news(10)
```

`@timer` 等价于：

```python
#原本 process_news 指向原函数。
process_news = timer(process_news)
#执行之后，process_news 指向的是 timer 返回的 wrapper 函数。
```
写法	接收内容
*args	所有位置参数，组成元组
**kwargs	所有关键字参数，组成字典
整个过程理解为下面这几个步骤：
1. 定义 process_news
   Python 创建原始函数对象。
2. 遇到 @timer
   自动执行 timer(process_news)，把原函数传进去。
3. 执行 return wrapper
   process_news 这个名字现在指向 wrapper。
4. 调用 process_news(10)
   实际上调用的是 wrapper(10)。
5. 记录开始时间
   start = time.time()。
6. 执行原函数
   func(*args, **kwargs)，执行 time.sleep(1)，返回 10。
7. 记录耗时并返回结果
   打印耗时，最后 return result。

**装饰器本质上是一个函数，它接收另一个函数作为参数。**
**wrapper 是包装函数**，负责在原函数执行前后增加功能。

**实践：**

项目中使用 Prefect 的 `@flow` 和 `@task` 装饰器，将普通 **Python 函数声明为工作流和任务**。

**局限与取舍：**

- 多层装饰器可能增加代码阅读难度。
- 不合理的装饰器可能影响函数签名和调试。
- 使用 `functools.wraps` 可以保留原函数的名称和文档等元信息。

### 5. 迭代器与生成器

**定义：**

- 可迭代对象（Iterable）：只要一个对象可以被 for 循环遍历，通常就可以称为可迭代对象。
**可迭代对象**
  
| 类型       | 示例                    |
| ---------- | ----------------------- |
| 列表 list  | `[1, 2, 3]`             |
| 元组 tuple | `(1, 2, 3)`             |
| 字符串 str | `"hello"`               |
| 字典 dict  | `{"a": 1, "b": 2}`      |
| 集合 set   | `{1, 2, 3}`             |
| 文件对象   | `open("test.txt")`      |
| range 对象 | `range(10)`             |
| 生成器     | `(x for x in range(5))` |
- 迭代器（Iterator）：迭代器是一种能够逐个提供数据的对象。
迭代器有两个核心方法：
- __iter__()：返回迭代器自身。
- __next__()：返回下一个元素，没有元素时抛出 StopIteration。
  注意：迭代器通常是**一次性**的，遍历完之后不会自动从头开始。

- 生成器（Generator）：生成器是一种特殊的迭代器，通常通过 yield 创建。
**目的：**

逐个处理数据，避免一次性将大量数据加载到内存中。

**原理：**

迭代器通过 `next()` 获取下一个元素，没有元素时抛出 `StopIteration`。

生成器执行到 `yield` 时会暂停，并保存当前执行状态，下次调用时从暂停位置继续执行。

```python
def read_news(news_list):
    for news in news_list:
        yield news

news = ["新闻A", "新闻B", "新闻C"]

for item in read_news(news):
    print(item)
```

iter(list) 返回的不是原来的 list，而是一个新的列表迭代器对象。

| 对比     | yield            | return               |
| -------- | ---------------- | -------------------- |
| 作用     | 生成一个值并暂停 | 返回结果并结束函数   |
| 执行方式 | 可以多次恢复执行 | 执行到 return 就结束 |
| 常见用途 | 生成器、惰性计算 | 普通函数返回结果     |

yield 和 return 最大的区别是：yield 可以暂停函数执行，并在下次迭代时从暂停位置继续执行；return 会直接结束函数。

Python 中，列表是可迭代对象，实现了 __iter__() 方法，可以返回一个迭代器，但列表本身没有实现 __next__()。这是因为列表主要负责存储数据，而迭代器负责维护遍历状态和逐个返回元素。这样可以让同一个列表创建多个独立迭代器，互不影响。

记住一句话：**列表负责存数据，迭代器负责记位置和取数据。**

**实践：**

项目处理大量新闻数据时，可以使**用生成器逐批或逐条读取**，减少内存占用。
生成器常见应用：
- 读取大型文件，避免一次性加载全部内容。
- 批量处理数据。
- 按需生成数据。
- 处理新闻采集、数据清洗等流水线任务。

```python         
#逐行读取文件：
  def read_news(file_path):
    with open(file_path, "r", encoding="utf-8") as f:
        for line in f:
            yield line.strip()

for news in read_news("news.txt"):
    print(news)
```
每次只生成一行，不需要把整个文件一次性加载到内存。
**局限与取舍：**

- **生成器通常只能向前迭代**，不能像 list 一样随意通过索引访问。
- 生成器一般不能重复遍历，耗尽后需要重新创建。
- 如果数据规模较小且需要反复访问，list 更方便。

### 6. `*args`、`**kwargs` 与类型提示

**定义：**

- `*args`：接收任意数量的位置参数，保存为 tuple。
- `**kwargs`：接收任意数量的关键字参数，保存为 dict。
- 类型提示：通过语法标注变量、参数和返回值的预期类型。

**目的：**

提高函数参数的灵活性和代码可读性，让调用方更容易理解函数接口。

**原理：**

```python
def analyze_news(title, *args, **kwargs):
    print(title)
    print(args)
    print(kwargs)

analyze_news(
    "AI新闻",
    "LLM",
    "RAG",
    importance=8
)
```

类型提示：

```python
def get_news(news_id: int) -> dict:
    return {"id": news_id, "title": "AI新闻"}
```

类型提示主要用于静态分析、IDE 提示和代码维护，Python 默认不会因为类型提示而自动进行运行时校验。

**实践：**

项目中的函数使用类型提示描述参数和返回值；Prefect 装饰器、通用工具函数也可能使用 `*args` 和 `**kwargs`。

**局限与取舍：**

- `*args` 和 `**kwargs` 过度使用会让函数接口不够明确。
- 类型提示不能替代运行时数据校验。
- 对外部输入可以结合 Pydantic 等工具进行校验。

## 三、学习复盘
    今日学习内容测试：
- Python 中可变对象和不可变对象的区别，函数传递参数时究竟传递的是什么？
  是否能在原数据基础上修改， 内存地址？
  可变和不可变的核心区别是对象创建后，能否修改**对象本身的内容**，而不是简单看内存地址是否变化。
  Python 采用**对象引用传递**（也常称为**共享对象传递**）：函数参数获得的是**传入对象的引用**。
Python 中，可变对象可以在原对象上修改内容，例如 list、dict；不可变对象创建后不能修改内容，例如 int、str、tuple。Python 函数传递的是对象引用，函数参数和外部变量可能指向同一个对象，因此修改可变对象会影响外部；但如果只是给参数重新赋值，不会改变外部变量的指向。

- 浅拷贝和深拷贝分别复制了什么？为什么嵌套列表可能出现修改一个对象、另一个对象也发生变化的情况？
  浅拷贝复制了一个外壳，共享内存地址，深拷贝递归复制内部结构
  浅拷贝：创建一个新的外层对象，但**内部嵌套的子对象**仍然共享引用。
  深拷贝：**递归复制对象及其内部成员**，尽可能创建独立的对象结构。
  因为 a 和 b 虽然外层列表不同，但它们内部的第一个子列表是同一个对象。

浅拷贝创建一个新的外层对象，但不会递归复制内部嵌套对象，因此内部对象仍然共享引用。深拷贝会递归复制内部对象，减少不同对象之间的**引用共享问题**。嵌套列表使用浅拷贝时，修改内部子列表会影响另一个对象。

- 装饰器的本质是什么？@decorator 为什么可以在不修改原函数的情况下增加功能？
  函数嵌套，因为装饰器内部有一个包装函数，在不修改原函数基础上，增加功能
  **装饰器接收原函数作为参数，并返回包装后的函数**。
装饰器本质上是一个高阶函数，**接收一个函数作为参数，并返回一个包装函数**。通过包装函数在原函数执行前后增加功能，例如计时、日志、权限校验等。@decorator 是语法糖，等价于 func = decorator(func)。

- 生成器为什么可以节省内存？它和普通列表在执行方式上有什么区别？
  因为可以不一次生成，普*通列表有iter方法没有next方法*
  列表和生成器的核心区别不是有没有 __next__()，而是数据如何产生和存储。
生成器是一种特殊的迭代器，通常通过 yield 或生成器表达式创建。它采用惰性计算方式，不会一次性生成所有数据，而是在调用 next() 或**遍历时按需产生数据**，因此适合处理大量数据，可以降低内存占用。列表则通常一次性生成并保存所有元素。

- *args 和 **kwargs 在函数调用、装饰器和框架源码中分别有什么作用？
  可以不固定函数**参数**数量，更灵活   它们本质上是为了**让函数可以接收不确定数量的参数**。
***args 用于接收不定数量的位置参数，保存为元组**；****kwargs 用于接收不定数量的关键字参数，保存为字典**。它们可以用于灵活的函数定义、参数解包和参数转发，在装饰器中尤其常见，可以让**包装函数兼容不同参数形式**。在框架中也常用于封装通用调用接口。
